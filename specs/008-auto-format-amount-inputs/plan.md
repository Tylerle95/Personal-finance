# Implementation Plan: Auto-Format Amount Inputs

## Summary

Implement auto-formatting for numeric amount inputs across the Personal Finance app. When typing money values:
1. For **VND** currency, the input will format with `.` as the thousands separator and reject any decimals (integer-only).
2. For **USD** currency, the input will format with `,` as the thousands separator and allow a single `.` as a decimal separator.
3. Submissions to Server Actions will use a hidden input field named with the target field name containing raw numeric strings (e.g. `33000000` instead of `33.000.000` or `1250.5` instead of `1,250.5`) to prevent parsing bugs.
4. Input cursor positions are preserved programmatically during keystroke formatting so user input is not disrupted.

We will build a reusable controlled component `FormattedAmountInput` inside `src/components/ui/FormattedAmountInput.tsx` to handle these capabilities.

## Technical Context

**Language/Version**: TypeScript / React (Next.js 16)

**Primary Dependencies**: React state, HTML5 forms, Server Actions

**Storage**: Supabase database (tables: `asset_accounts`, `asset_transactions`)

**Testing**: TypeScript compilation check, ESLint checks, local development browser validation

**Target Platform**: Next.js Web App

**Project Type**: Web Application

**Performance Goals**: Instant formatting feedback on key press (< 10ms render latency)

**Constraints**:
- Cursor position must be preserved exactly, even when separators are added/removed.
- Deleting a separator (dot/comma) using Backspace or Delete must automatically remove the adjacent digit to prevent the user from getting trapped.
- Physical quantities (like BTC quantity or shares count) are excluded from currency auto-formatting and will remain standard numeric inputs.
